# v0.2.0-rc.2 — 前回監査6件の修正報告

対象は会話内のv0.2.0-rc.1配布ZIP（SHA-256 `2dbf80214c09a184f45efee3dc98fcd4458ba2d64748fe000d23168c198ef82d`）です。新規機能を増やさず、再現済みの制御・入力・配布問題を修正しました。GitHub上の別ソースを変更したものではありません。

## 修正結果

| ID | 問題 | 実装した変更 | 回帰試験 |
|---|---|---|---|
| R01 | 先読みが完成済みの2文目を止める | 次ターンの先読みを独立タスク化。送出ループでは完了を待たず、単一準備枠と例外回収を維持 | 未完了の先読み中でも2文目を送出。実200msワーカーでも3秒の保留中に送出 |
| R02 | 先読み失敗が200ms周期で再試行される | 生成専用の失敗回数・再試行期限を追加。再生用の間隔や終了ACKと分離 | 再生中でも2秒以上待つ。ACK後も失敗回数と2秒→4秒の期限を維持 |
| R03 | 話題変更時に採用コメントを失う | コメントの予約・準備・送出・再生・完了を追跡。未送出の取消は期限・セッションが有効なら一度だけ再キュー | 話題移動と返答準備が重なっても再キューし、再生完了まで追跡 |
| R04 | 古い準備済み返答を流す | 最初の送出直前にTTLとセッションを再検査。期限切れは理由つきで破棄 | 準備後の期限超過を音声・字幕送出前に破棄。すでに始めた返答は文の途中で切らない |
| R05 | 改行入り人格を保存できない | 人格だけCRLF/CR→LFを正規化しLF/タブを許可。2000文字・制御文字検査を維持。エラーに項目名を返し入力欄に表示 | 保存API経由で改行を保持。キーの改行、NUL、上限超過を拒否し値はエラーに出さない |
| R06 | 配布物に.gitignoreがない | .gitignore/.npmignoreをソースZIPとtgzへ明示同梱。私的ファイルを検出したら配布前に拒否。Gitで一時ソースZIPを作成 | ダミー.env/dataが通常Git追加やZIP/tgzへ入らず、.env.exampleは残る |

単一のコメントは、候補または準備・再生処理のいずれかが所有します。予約中・再生中も判定済み2枠へ数え、取消中に別候補を判定して上限を超えないようにしました。

「もう送ったが聴取が分からない」返答は、重複を避けるため自動で先頭から再生しません。`interrupted_*`という破棄理由を記録します。未送出の候補だけが復帰対象です。破棄ログはIDと理由であり、コメント本文やキーを記録しません。

### 速度試験の意味

3秒保留するLLMも503を返すAPIも、外部サービスではなく模擬依存です。実ワーカーの制御を確認するもので、Jev・LLMの実際のレイテンシー、500ms/800ms達成、YouTubeの視聴者到達を測定したものではありません。

## 配布・更新

ソースZIPは `npm run pack:release` で再生成できます。許可したファイル一覧を確認して一時スナップショットを作り、そこからZIPとtgzを作成します。既存Gitリポジトリへのcommit/pushやnpm公開はしません。SHA-256とファイル別ハッシュも出力します。

更新は [UPGRADE.md](UPGRADE.md) のとおり、旧版を停止して別フォルダへ展開します。保存済み設定を引き継ぐ場合は私的な`data/`を安全に移し、実試聴をやり直してください。

`.gitignore`は既追跡の秘密ファイルや強制追加を防ぎません。任意のファイルに書かれた秘密を網羅的に発見する秘密検査でもありません。独自のDATA_DIR、手書きのメモ・録音を公開しないよう確認してください。
