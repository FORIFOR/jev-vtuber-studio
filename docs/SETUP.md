# 初回接続ガイド / Setup

急ぐときは [最短手順（1ページ）](QUICKSTART.md)。

対象：0.2.0-rc.3。Node.js 22.12以降を事前導入。通常は `npm start` または起動ファイルを実行し、表示されたControl URLを開く。デモの強制起動は `npm run demo`。

## 0. 準備状況を一画面で見る

設定ページ（`/setup`）の先頭「準備状況」で **いま確認する** を押すと、会話モデル・ホストの声・コメント読み上げ・Jev キー・試聴の確認・OBS 接続・OBS 専用シーン・（Switch のゲームなら）映像機器・YouTube 配信枠を一度に問い合わせ、✓／✗／－（不要）で並べます。各行の「開く」が直す場所へ飛びます。DEMO では会話モデル・Jev・試聴は－になります。録画の確認だけは自動判定せず、人が録画を再生して確かめます。接続先に問い合わせるだけで、配信・録画・ゲームは何も始めません。

操作が失敗したときは、管理 URL で開いている画面に「（原因: …）」が付きます。URL・鍵・ホーム以下のパスは伏せた上での原因で、閲覧トークンの画面には出ません。同じ内容は `data/events.jsonl` にも残ります。

## 1. AI・声を準備する

### ローカルの会話モデル

Ollamaなどを利用者が導入し、利用条件を確認したモデルをダウンロード・起動する。接続ガイドのプリセットでOllamaを選択。既定URLは `http://127.0.0.1:11434/v1`。内部では末尾 `/v1` を取り除きnative `/api/chat` を使う。`think:false`、`keep_alive:30m`を要求する。モデル側の対応は実試聴で確認する。

最初にDEMOのままでURLを保存し、「モデルと声を検出」。一覧に出た導入済みモデルを選び、名前を保存する。モデルは自動で取得しない。VRAM適合や日本語品質は利用モデル次第。

LM StudioはプリセットのローカルURLと、実際に公開されているモデルIDを設定。Geminiはキーと、アカウントで使えるgenerateContentモデル名を入力。Ollamaクラウドモデルを選ぶとローカル動作とは異なるため、モデルの実行先を確認する。

### VOICEVOX

VOICEVOX Engineを別途起動。既定URLは `http://127.0.0.1:50021`。声のスタイルを検出・選択し、クレジットを保存する。検出された表記は便宜的な初期値で、利用条件の適合を保証しない。

標準経路は `/audio_query` → `/synthesis` → WAV。1文ずつ全量を受け取る。TTSをローカルで使う場合もCPU/GPUと電力を消費する。

### AivisSpeech / Style-Bert-VITS2 と声の演技（任意）

ホストの声は VOICEVOX・Supertonic 3 のほか、AivisSpeech Engine（既定 `http://127.0.0.1:10101`）と Style-Bert-VITS2（`server_fastapi.py`、既定 `http://127.0.0.1:5055`）を選べます。導入時の注意（ポート、ファイアウォール、ライセンスとクレジット表記）、`HOST_STYLE_MAP`、演出モード `SPEECH_DIRECTION`、反応音と定型フレーズのライブラリ（`npm run voice:library`）、聞き比べ（`npm run voice:bench`）は [VOICE.md](VOICE.md) を参照してください。既定では演出は無効で、従来の声の経路のままです。声やライブラリを変えたら実試聴をやり直します。

### Jev

TypeSafeの自分のキーを入力して保存。キーは保存後ブラウザへ返さない。空欄の保存は維持、専用削除ボタンは削除する。キー入力に成功したこととAPI利用可能なことは別なので、次の実試聴を必ず行う。

## 2. 実試聴

外部送信・使用料のチェックを確認して実行。モードはliveに切り替わる。実生成→出力判定→実WAV合成の各結果と時間が表示される。

音声の再生ボタンを押し、最後まで聞いた後、「聞こえた」を押す。サーバーは操作者の申告を記録するが、スピーカー出力の物理的検出ではない。音量、発音、キャラクターとの一致を人が確認する。

この試聴だけではOBS・YouTubeの音声を確認していない。モデルや声が変わった場合・サーバー再起動時は試聴をやり直す。設定画面の保存は停止中のみ。エラー時に他の有料APIへ勝手に切り替えない。

## 3. YouTube

Google側でYouTube Data APIを有効にして利用可能なAPIキーを取得し、配信枠の動画URLを入力する。対象はチャットを読める公開ライブ。非公開・制限付き配信のアクセスを保証しない。キーはYouTube Data APIに用途を制限する。Nodeサーバー呼び出しにブラウザHTTPリファラー制限を付けると適合しない場合があるため、アカウントの設定とエラーを確認する。

`streamList`用の追加依存を導入：

```sh
npm run setup:youtube
```

提供コードのバージョン指定：`@grpc/grpc-js@1.14.0`、`@grpc/proto-loader@0.8.0`。この環境では導入・wire接続は検証できていない。依存の更新・脆弱性・推移依存の解決結果は利用環境で確認する。固定バージョンだけで完全な再現性や安全性を保証しない。導入失敗時は表示付きpollingへ退避する。

接続チェックは動画の配信状態を確認する。実コメントの受信試験ではない。未配信なら「配信開始待ち」。番組の開始後も対象を再確認し、配信開始時に接続する。終了した動画を次回使い回さず、新しい動画URLを設定する。

必要時のOAuthは `.env.example` のCLIENT_ID / CLIENT_SECRETと `npm run youtube:auth` を利用。Desktopアプリ認証の設定が必要で、完全なGUI化の対象外。要求スコープは読み取り専用。トークンは `data/youtube-oauth.json`。APIキーとOAuthの両方が設定されている場合はAPIキー経路を優先する。

## 3.5 企画の言葉を書き換える

設定ページ「企画の編集」で、企画名・画面に出す問い・狙い・最初の挨拶・締めの言葉・各段階の課題と見本の台詞を書き換えられます。「検証して保存」は、組み込みの企画と同じ基準（見本は 2 文・180 文字以内、課題は重複なし、段階の数とゲームの指定は固定）で検証し、通ったものだけを `data/programmes/<id>.json` に保存します。次の番組開始から使われ、`config/programmes.json` は書き換えません。「組み込みの内容に戻す」で保存した編集を捨てます。読めない編集ファイルは無視して、その旨を表示します。

キャラクターの名前・番組名・話し方は設定ページ 01 で、OBS プロファイル名・BGM ソース名・Twitch チャンネルの既定は `config/character.json` の `obs` / `twitch` で変えられます（`.env` の `OBS_*_PROFILE` / `OBS_BGM_SOURCE` / `TWITCH_CHANNEL` が優先）。コードに固定された名前はありません。

キャラクター固有の**内容**（コードではなく文章）が残る場所は次の 3 つで、キャラクターを替えるときはここを書き換えます。
- `config/programmes.json` の企画本文（例: `noa-vampire` / `noa-smash` の「名前の話」の段階）。設定ページ「企画の編集」で変えられる。
- `config/lobby-scenes.json` のゲーム前の小話（`noa-short-answer`、`hoshiai-letterplay` など名前を題材にした場面）。`data/lobby-scenes.json` に同じ形で置くとそちらが使われ、形が合わなければ組み込みに戻して「準備状況」に表示する。
- `config/character.json` の `persona` / `topics` / `memoryPins`。設定ページ 01 の「話し方」で上書きできる。

## 4. OBS / 音声所有権

OBSを導入し、ブラウザソースとWebSocketが利用できることを確認。接続ガイドにURLとパスワードを保存して接続確認。

1. スタジオを停止し、「OBSに専用シーンを作る」を操作。
2. OBSに作成される `Jev Studio` / `Jev Stage` を確認。同名ソースを更新するため、自分の専用シーンで使用する。
3. 管理画面プレビューを無音にし、OBSのブラウザソースが音声を所有することを確認。
4. 自動運転を開始し、必要ならOBSブラウザソースの「対話」で音声を有効化。
5. OBSの音声メーターとローカル録画を確認。デスクトップ音声も同時に収録して二重になっていないか聞く。

放送先、ストリームキー、公開範囲、超低遅延などはYouTube/OBS側で設定する。AIへストリームキーを渡さない。初回は限定公開で操作と会話品質を確認。

「外部配信を許可」の保存と、スタジオでの明示的な配信開始確認を別に行う。既にOBSから手動で始めた他の配信はStudioが所有しないため、Studioの停止で止まるとは限らない。OBS側で停止確認する。

## 5. 保存・移行

別の Mac（Mac mini など）へ移して配信するときの準備物と手順は [MOVE_TO_ANOTHER_MAC.md](MOVE_TO_ANOTHER_MAC.md) にまとめています。

v0.1.0を稼働させている場合は停止し、新版を別フォルダへ展開。旧dataを無条件コピーせず、まず新しい接続ガイドで設定し直す。旧版を残して戻せるようにする。

`data/settings.json`が `.env` より優先。設定保存は平文、Unix0600。ソースは保存したキーをブラウザへ返さないが、同じOSユーザー権限の他プロセスやバックアップからは読み取られ得る。Windowsの権限は自分で管理する。

localhost限定で、遠隔公開・自動常駐・再起動後の無人再公開は初版の対象外。システム設定や安全装置を無効化して動作させない。

## スマホ操作（任意）

PC側のセットアップ完了後、[REMOTE.md](REMOTE.md)に沿って限定ゲートウェイを追加します。フル管理画面やOBSの直接公開は行いません。
