# スマホから配信を開始する — rc.3

**PCは放送装置、スマホはリモコンです。** 初回設定とPC側の試聴・録画確認後、許可されたスマホから「配信を開始 → 対象を確認 → 確認して開始」で、自律雑談とOBSの送出を始めるための機能です。スマホを閉じてもPC側の処理は継続します。

本版はリリース候補です。ソース実装・ローカルHTTP・模擬OBSでの制御は試験済みですが、実Tailscale、iPhone Safari、実OBS・YouTubeでの遠隔配信は未検証です。接続設定や認証を利用者の環境で実行したものではありません。

## 1. 対象と前提

対応するのは**起動済みPCを遠隔操作する方式**です。Node.js 22.12以降、Jev Studio、OBS、会話モデル、VOICEVOX EngineをPCで起動し、スリープしない運用にします。OBSのブラウザソースが生きたデスクトップセッションを使ってください。画面ロック時のOBS動作・音声・GPUは自分の環境で検証します。

電源OFFやスリープからのPC起動、OBSアプリの遠隔起動、OSログイン、クラウドGPU起動、新規YouTube枠作成、任意動画ファイルの再生は実装していません。スマホ単体で映像を生成するアプリでも、スマホカメラを配信するアプリでもありません。

## 2. 構成

```text
スマホ Safari / ホーム画面
  → Tailscaleのプライベートネットワーク
  → Tailscale Serve HTTPS（利用者IDを付与）
  → 127.0.0.1:8788 専用リモコン（開始・停止・状態のみ）
  → PC内部の番組制御とOBS WebSocket
  → PC内OBSのブラウザソースで描画・音声
  → YouTube

PC専用管理画面: 127.0.0.1:8787（外部へ転送しない）
OBS WebSocket: 通常127.0.0.1:4455（外部へ転送しない）
```

初期状態は遠隔操作無効です。スマホに管理トークン・配信用トークン・OBSパスワード・YouTubeストリームキーを渡しません。スマホは音声再生権を取得しません。既存の設定画面やステージをそのままネットへ公開する構成ではありません。

## 3. 初回だけ行うネットワーク設定

PCとiPhoneへTailscaleを公式手順で導入し、同じプライベートネットワークに参加させます。スマホは個人の利用者IDでログインする端末を想定します。タグ付き端末からはこの機能が依存する利用者ヘッダーが付かないため、この版では拒否します。

Tailscale側のアクセス制御を、操作者の端末・利用者だけがこのPCのHTTPSへ届くように制限してください。ServeにはHTTPS証明書の有効化が必要です。初回の公式CLIが求める同意を確認してください。

Tailscaleの管理画面またはPCの状態表示で、PCの完全なDNS名と自分のログイン名を確認します。以下の名前・メールは例なので、そのまま使わないでください。

```sh
npm run remote:setup
```

対話でPCのHTTPS URLと、許可するログイン名を入力します。非対話で設定する場合:

```sh
npm run remote:setup -- \
  --origin=https://YOUR-PC.YOUR-TAILNET.ts.net \
  --user=YOUR-LOGIN@example.com \
  --confirm-private-network
```

保存先は非公開の`data/remote-control.json`、Unixのファイル権限0600です。アカウントを勝手に作成せず、ポートやファイアウォールを変更しません。既存設定の上書きには`--replace`が必要です。設定後にStudioを再起動してください。対話設定は1利用者を登録します。手動の許可リストは最大5利用者です。

**既存のServe設定を確認してから**、専用のリモコン用ポートだけを転送します。他の用途のHTTPS公開先を意図せず置き換えないでください。

```sh
tailscale serve status
tailscale serve --bg --https=443 http://127.0.0.1:8788
tailscale serve status
```

`--bg`はTailscale Serveのバックグラウンド運転指定です。Jev Studio・OBS自体を起動するコマンドではありません。ゲートウェイを別ポートに設定した場合はそのポートへ合わせます。

**Funnelは使用しません。8787や4455の転送、0.0.0.0での待受、ルーターの一般公開ポート開放も行いません。** Serveはプライベートネットワーク向けです。Serveのユーザーヘッダーを付与しない別プロキシへの置き換えは非対応です。

## 4. 出かける前のPC側チェック

サーバー再起動や重要設定の変更後には、以下を再確認します。ネットワーク設定が保存されていても、遠隔開始の許可は勝手に復元しません。

1. PCで実APIの雑談モード、モデル・VOICEVOX、YouTube動画URL、OBS接続、外部配信の許可を設定します。実試聴を行い、「聞こえた」を確認します。
2. ローカル番組を止めた状態で「OBSに専用シーンを作る」を実行します。本版からOBS専用の再生識別子をURLに付けるので、旧版のソースをそのまま使わないでください。再起動後も同じ操作で現在の識別子へ更新します。
3. 管理プレビューを無音にし、OBS側の専用ソースへ再生権を渡します。OBSのソースは表示、音声ミュート解除、音量ゼロ以外にします。必要ならOBSの「対話」から音声を有効にします。
4. ローカル自動運転を短く行い、**OBS内で実WAVを再生**します。OBS録画を聴き、声・字幕・口パク・二重再生の有無を確認します。ブラウザからの再生終了通知だけで聴感を保証しません。
5. ローカル番組とOBS送出を止めます。OBSアプリ、専用シーン、ブラウザソース、各エンジンは起動したままにします。
6. YouTube側で正しい動画ID・公開範囲・OBSストリームキーの対応を確認し、エンコーダーから公開を開始するなら**自動スタート**を有効にします。送出終了で枠も終了させる運用なら**自動ストップ**も設定してください。
7. 接続ガイド「05 スマホから開始」で録画・送信先の確認欄をチェックし、**遠隔開始を8時間許可**します。

遠隔開始許可はこのプロセス内のメモリだけに置きます。8時間経過、サーバー再起動、設定保存、明示解除、緊急停止で無効になります。期限後も、接続できる許可済みスマホからの停止は受け付けます。再許可はPCで行います。

試聴済みのモデル・声・人格、YouTube動画ID、OBS接続先、配信時間に許可を結び付けています。OBSの実際の配信サービス設定、専用シーン・ソース・表示状態・音量も開始前に確認します。ストリームキーそのものはPC内でハッシュ化に使い、スマホへ返しません。異なるサービス設定やソースへ無言で切り替えて開始しません。

**YouTube側の公開範囲や動画とキーの対応は、PCでの操作者確認です。リモコンがYouTubeの管理APIで独立に検証する機能はありません。** 新しい配信枠に変わった場合はPCで設定・確認をやり直します。終了済み枠を自動再作成しません。

## 5. スマホからの操作

Tailscaleを接続して、設定したPCのHTTPS URLの`/mobile`をSafariで開きます。APIキーやControl URLをスマホへコピーしません。

「開始できるか確認」では、開始せずに条件を調べます。「配信を開始」を押すと、タイトル・配信時間・動画IDを表示する確認画面が開きます。「確認して開始」で初めてPCへ開始要求を送ります。API利用料が発生する可能性があります。

```text
開始条件を確認 → OBSへ送出開始 → OBSのactive状態を観測
  → PCの自律雑談を開始 → 状態欄にOBS送出中
```

Safariの共有メニューからホーム画面へ追加するためのmanifestとアイコンを同梱しています。iOSの追加・通知・バックグラウンド動作を実機で保証したものではなく、App Store配布のネイティブアプリでもありません。オフライン操作キューは設けていません。

スマホを閉じても番組は続きます。開き直したときはPCの状態を取得し直し、開始命令を再送しません。スマホで別のアプリを使っても、PCの音声再生先をスマホへ切り替えません。

「配信を停止」は現在の発話も含めてローカル番組を止め、Studio自身が開始したOBS送出の停止を試みます。「緊急停止」はそれに加えて再開を禁止し、遠隔開始許可を取り消します。緊急停止解除はPCで行います。通常の終了挨拶はPC側の番組制御で扱い、スマホの停止は即時停止を優先します。

## 6. 表示と通信の限界

- **OBS送出中**: OBSからactiveかつ非再接続の状態を取得したこと。YouTubeの公開開始や視聴者の映像・音声到達の証明ではありません。画面の視聴ページリンクも確認します。
- **停止を確認できません**: StopStreamを依頼しただけで終了と断定できない状態。自分の送出がactiveのままなら他人の配信と誤表示せず、停止未確認にします。PCのOBSとYouTubeを確認してください。
- **別途開始したOBS送出が継続中**: Studioに所有権のない既存配信は勝手に止めません。専用OBSセッションで運用してください。
- スマホの圏外・PCのネット断・停電・スリープ中は、開始も停止も届きません。接続喪失を理由に勝手な再開始はしません。通信が切れてもPCが健全なら30分等の番組時間制限は継続します。
- 開始時間は未実測です。モデルの読み込み、ネットワーク、OBS、YouTubeの準備に依存し、「押して1秒で公開」を保証しません。モデルサーバー起動中でもモデル重みが退避していれば初回生成は遅くなります。

## 7. セキュリティ境界

`Tailscale-User-Login`を、その機械の信頼するTailscale Serveからだけ受ける構成です。Serveは外から来た同名ヘッダーを除去して付与します。アプリはloopbackアドレス・完全一致Host・明示利用者リストを確認します。**同じPC上の悪意あるプロセスはこのローカルヘッダーを偽装できるので、共有・非信頼ホスト向けの認証ではありません。** Tailscale ServeやOSの侵害を防ぐ仕組みではありません。

認証済みCookieはHttpOnly・Secure・SameSite=Strict、操作には同一Originとセッション固有のCSRF値を要求します。セッションは最大12時間、同時32個、メモリ保存です。スマホ側に管理キーやlocalStorageの秘密を置きません。設定した利用者の別端末も同じログイン名になるため、端末単位の制限はTailscale側でも行います。

公開APIは状態・確認・開始・停止・緊急停止だけです。設定変更、シェル、任意URLアクセス、任意動画選択、配信キー参照、再生権限取得はできません。開始等は1セッション20回/分、停止はこの制限で遅らせません。操作IDによる重複防止は最新128件・現プロセス内で、サーバーをまたぐ永続的なexactly-once保証ではありません。過去の操作IDを再利用したら過去結果を返し、新しい配信を開始しません。

初回公開前には専門的な認証・遠隔制御レビューと実環境の接続試験を推奨します。ローカルの模擬ヘッダー試験は実VPNの認証成功の証拠ではありません。

## 8. 停止・無効化とトラブル

すぐに新たな遠隔開始を拒否するにはPCの接続ガイドで「遠隔開始の許可を解除」を押します。これは現在の配信を終了する操作ではありません。配信も終了する場合は停止を操作してください。

設定から無効化するには`npm run remote:setup -- --disable`を実行してStudioを再起動します。Tailscale Serve自体の設定解除は別途行い、他のサービスまでまとめて消さないでください。Tailscale公式のdisable手順と`tailscale serve status`を確認します。

403はTailscale未接続、利用者の不一致、Funnelや別プロキシ、Hostの不一致などを確認します。401はページを開き直します。SOURCE_CHANGED/OBS_AUDIO_REQUIREDはPCで専用シーンを更新して、OBSが音声を所有しているか確認します。REHEARSAL_REQUIRED/OBS_REHEARSAL_REQUIREDはPC側の実試聴・OBS録画確認をやり直します。STOP_UNCONFIRMEDを成功扱いにしません。
