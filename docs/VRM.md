## 起動と切り替え

> **2026-10-03 モデル**: `public/models/noa3d/Noa.vrm` は 4.92 候補（4.91 に加えて約6頭身（頭 1.12 倍・首 −10%・脚 −4%）、無地のジャケットと指先までの袖、ひし形のヘアピン、厚底スニーカー、MToon 輪郭線。正式設定画への寄せ：卵型の輪郭と大きめの目、暖色の肌、茶黒の緩いウェーブ髪と目にかかる前髪・アホ毛、長めのオーバーサイズジャケットと前後の縦ストラップ・フード背面の猫、猫ロゴと発光リングのヘッドセット、茶系半透明タイツ、厚底スニーカーと発光ライン。約67 MB、SHA-256 は `manifest.json`）。4.91 以上はモデル自身が顔の輪郭と肌・髪の陰影を持つので、実行時の顔補正（`face-fit.mjs`）は使わず、材質調整（`material-finish.mjs`）も肌と髪には掛けない（`modelHasOwnFace`）。以下の本文は 4.86 時点の記述を含みます。制作と検証の記録は `~/Documents/ChatGPT/AIRoid_3D/Noa_Codex_Production_Kit/evidence/ITERATION_LOG.md`。OBS・音声同期は 4.91 では未確認です。

管理画面のホスト欄にある「配信アバター」で **2D / 3D** を選べます。2Dは従来のNoaパーツ画像アバター（NoaAvatarV4）、3DはNoa 4.86のVRMです。2Dを3Dへ変換したり、3Dを平面化して代用したりするものではありません。2DはCubism/Live2Dではなく、既存のPNGレイヤー方式です。

選択は `data/avatar-mode.json` に保存され、同じサーバーのStudioプレビューと閲覧トークン付きStageへ同期します。再接続・再起動後も復元します。未保存の場合は既存の配信を維持するため2Dで起動します。以前に3Dを保存している場合は3Dのままです。認証済みの通常Stageは保存値を受け取ってから選択されたアバターを読み込みます。2D選択時に3Dの53 MBモデルを先読みすることはありません。

`release/rc6-voice` の2026-09-30更新 (`285f2f4`) を取り込んでいます。新しい管理画面、ゲーム配信、同時配信、ラウンド講評、分析、メモリ保護を保持しています。管理画面のプレビューは最新版の仕様どおり休止状態で始まるため、映像を確認するときは「プレビューを再開」を押してください。休止中もアバターと衣装の選択を保存でき、接続中のStageへ通知されます。選択操作だけでプレビューを再開したり、OBS配信を開始したりはしません。メモリ警告時は再びプレビューを休止します。

この更新より前から開いている管理画面・Stage・OBSブラウザーソースは、一度再読み込みして新しい切替処理を読み込んでください。以後の2D/3D変更ごとに再読み込みする必要はありません。

ページを再読み込みせず、表示するアバターだけを切り替えます。読み込み中は直前の表示を維持し、成功後に入れ替えます。3Dから2D・SVG・外部合成へ切り替えた後は、VRMとWebGL資源を破棄してメモリを解放します。まだ表示されていない3Dの読み込みも、別の表示を選ぶと中止します。3Dに戻す際はモデルを読み直します。音声の再生・所有権・字幕・会話処理を切替操作から停止しません。3Dへ戻すと保存済み衣装と現在の表情・口パク入力を使い、古い身振りは再開せず待機姿勢へ戻します。

`npm start` で起動し、起動ログのControl URLから管理画面へ入ります。モデルとブラウザー用ライブラリは同梱済みで、通常起動に追加の `npm install`、外部CDN、VTube Studioは必要ありません。3D表示にはWebGL2に対応したブラウザーが必要です。

個別の表示を固定したい場合は、従来のURL指定も利用できます。

- `avatar=vrm`: Noa 3Dに固定。
- `avatar=noa`: 既存の2Dパーツ画像。
- `avatar=builtin`: 既存SVG。
- `avatar=external`: アバター非表示。外部キャプチャとの合成用。
- `renderer=v3`: 従来の軽量2D。`avatar`を明示していない場合のみ2Dを選択。

指定は既存のStage URLのフラグメントに `&avatar=noa` のように追記するか、`/stage?avatar=noa` のクエリーに追加します。**明示したURL指定は管理画面の共有選択より優先されます。** 共有切替に追従させるOBSブラウザーソースでは `avatar=...` と `renderer=v3` を外してください。通常の「OBSに専用シーンを作る」は固定指定を付けません。ただしVTube Studio連携が有効なときの `avatar=external` は外部合成用として維持します。

閲覧トークンは引き続きフラグメントに置き、URLやスクリーンショットを公開しないでください。縦画面は従来どおり `layout=vertical` です。最新版の外部ゲーム用 `layout=game`、透過重畳用 `layout=overlay` でも2D/3Dを切り替えられます。ゲーム待機中の中央配置とプレイ中の右側配置に3D用の寸法を設定しています。未認証Stageは共有設定を取得せず、URL指定または初期値を使います。

VRMの読み込み・WebGLの作成に失敗すると既存2Dへ、2Dも読み込めなければSVGへ戻ります。2Dへの切替が失敗しても3Dが正常表示中なら3Dを維持します。開発者コンソールに理由を記録し、管理画面に選択・実表示・読込中・代替表示を区別して表示します。失敗した3Dを再試行するには2Dを選んでから3Dへ戻します。

内部状態は `#canvas` の `data-avatar-mode`（実表示）、`data-avatar-requested-mode`（選択）、`data-avatar-mode-source`（共有/URL固定）、`data-avatar-state`（読み込み状態）で識別できます。保存成功や代替表示を3D表示成功とは扱いません。

`GET /api/avatar/mode` は閲覧または管理権限、`POST /api/avatar/mode` は管理権限が必要です。本文は `{ "mode": "noa" }`（2D）または `{ "mode": "vrm" }`（3D）です。認証・Host・Origin制限は従来どおりです。

## 着せ替え

管理画面の「3D衣装」で次の3つのプリセットを選べます。2D選択中は変更欄を無効にし、保存済みの3D衣装は保持します。2Dの衣装画像には適用しません。

| 衣装 | 変更点 |
| --- | --- |
| 白×青パーカー | 元の4.86の衣装。既定値。 |
| チャコールパーカー | 布と配色をダーク系に変更。フードあり。 |
| フードなしジャケット | フード・ひも・対応する付属部品を非表示にしたジャケット。 |

同じ衣服メッシュを使った配色・フード構成のバリエーションです。新しいスカートやワンピースを追加したものではなく、任意の衣装ファイルを読み込む機能でもありません。肩と袖を覆う胴体メッシュはどの衣装でも保持します。

選択はサーバーの `data/avatar-wardrobe.json` に保存し、接続済みのStageへイベントで反映します。StudioプレビューとOBSは、同じサーバーの閲覧トークン付きStageを開いてください。後から接続した画面にも保存済みの選択が届きます。未認証のStageは既定衣装のままです。

着せ替えでは53 MBのVRMを再読み込みせず、顔・髪・肌・骨格・表情・音声再生を変更しません。3Dが2D/SVGに退避している場合、衣装の選択は保存されますが、その2D画像は着せ替わりません。管理画面で保存状態とプレビュー反映状態を区別して表示します。

`GET /api/avatar/wardrobe` は閲覧または管理権限、`POST /api/avatar/wardrobe` は管理権限が必要です。POSTの本文は `{ "outfitId": "midnight-hoodie" }` のように指定します。`signal-hoodie`、`midnight-hoodie`、`studio-jacket` 以外は受け付けません。既存のHost・Origin・トークン検査は維持します。

## 制御の分担

Jevの採否判定・会話・記憶・TTS・音声所有権は変更していません。新たなAIサーバーも起動しません。

1. 既存 `AvatarController` が演技プリセット、まばたき、視線、演技の余韻を制御。
2. `browser/avatar-vrm/` がVRM表情・頭の姿勢に変換。
3. 収録済みのRocketboxモーションを正規化人体ボーンへリターゲット。固定の許可リスト以外は再生しない。
   - 「はしゃぐ」(`excited`) は採用イラストの招きポーズ `noa-beckon.vrma` を再生する（左手を差し出し、右手をヘッドホンの横へ、首を傾ける。約3.3秒）。このファイルだけは Rocketbox 由来ではなく、`node scripts/build-noa-beckon-motion.mjs` で再生成できる本リポジトリの自作（MIT）。従来の手振り `rb-wave.vrma` は許可リストに残しているが、現在どのリアクションにも割り当てていない。
   - 待機の見た目（設定画・`docs/REVIEW_v490.md` 追記2 A/E）: 配信者として演技している間は、軽い微笑み（`happy` 15%）＋頬染め（`blush` 20%）＋口角上げ（`happy` の口だけ 40%）を保つ。頬染めは色だけで、目を細める成分は待機時には使わない（4.92 の大きな目では半目に見えたため）。入力がないとき・ナレーター読み上げ中・口角が下がる演技のときは付かない。首は常に本人の右へ 8° かしげる（頭の回転は従来の上限 ±0.35rad を超えない）。
   - 待機が 40〜60 秒続くと `noa-beckon.vrma` を 1 回再生する（間隔は固定の数列で、乱数は使わない）。リアクション・ナレーターの番・停止・動きを減らす設定のときは数え直す。
   - ヘッドセットの発光リング（4.91 の材質 `Noa Reference AI ring`）は AI の状態表示: 話している間は声の大きさで明るくなり、待機中はゆっくり明滅、考え中・聞いている間は一定の中くらいの明るさ（`ai-ring.mjs`）。
   - 待機中は首のかしげと逆向きに肩を 3° 傾け、片足重心の印象にする。リムライトは 1.1（以前 0.65）。
   - 足元に接地影（半透明の楕円 2 枚）を置く。床が映る構図でだけ見え、現在のステージのバストアップ構図には映らない。
4. 髪はモデル内の衝突球・SpringBoneと1/120秒固定更新で追従。

停止検査で見つかった毛先の引っ掛かり対策として、4つの毛先関節にだけ弱い下向きの重力を補っています。モデルの衝突球・剛性・減衰とVRM本体のファイルは変更していません。変更値と計測結果は評価資料に記録しています。

顔の読み込み時には、顎前面を最大12 mm下げ、下側の横幅を最大8%絞ります。目元と首の接合部では変形量をゼロにし、顎の追加メッシュ・歯・表情モーフにも同じ変換を適用します。元のVRMファイル・骨格・衣装は保持し、毎フレームの再加工は行いません。胸から上のカメラ構図と合わせて輪郭を見やすくしています。

口の音量は実再生音声の解析値を使用します。音声クエリーに読みと発音時間がある場合は、その母音列を実際の再生時計に合わせます。AivisSpeechはクエリーの音素時間がダミー値のため、読みとWAVの発声・無音区間から推定します。**Aivisの時刻は強制アライメントや音声認識による実測ではありません。** 読み情報のない収録クリップや他のエンジンでは音量ベースの口パクを維持します。コメント読み上げ役の間は口を閉じ、閉口ハミング用の口制御区間も維持します。

3Dの眉は既存リグの眉位置・傾き・視線から控えめに変化し、待機中の笑顔や困り顔にも口角と目元を連動させます。感情プリセットの眉との二重加算を避け、瞬きと口パクを独立させます。新しいランダム動作やAI呼び出しは追加しません。

髪・肌・布・金具にはMToonの陰影と輪郭光を別々に調整しています。既存テクスチャ・透明度・アウトライン・衣装切替を保持し、影用の追加描画、後処理、描画解像度の増加はありません。新しい質感テクスチャやメッシュを制作した変更ではありません。

正確な音量口パクの入力を持つのは音声を所有する画面です。OBSが音声を所有するとき、スタジオの別プレビューに同じ音量信号を配信する機能は今回追加していません。二つの画面で二重に音声を再生させないでください。

音声終了・停止・接続切断時は身振りを待機へ戻し、口パクを停止します。途中の演技ビートも同じ制御経路で反映します。OSの動きを減らす設定では大きな身体動作を抑えます。

## アセットと配布

モデルは `public/models/noa3d/Noa.vrm`（約53 MB）。顔、肩を覆うパーカー、髪、表情の変更済み4.86をそのまま格納しています。SHA-256は同フォルダーの `manifest.json` と検査で固定しています。Git LFSポインターではなく実ファイルです。

サーバーはレビュー済みのVRM・VRMA・manifest・利用条件ファイルだけを固定許可リストで配信し、大きなモデルをストリーム転送します。CSPは埋め込みテクスチャ用に `img-src blob:` と `connect-src blob:` を許可します。後者はThree.jsのImageBitmapLoaderがモデル内画像をBlob URLからfetchするために必要です。外部HTTP接続先や外部スクリプトは追加しません。

モデル本体はMIT/CC0ではありません。`AVATAR-LICENSE.md`、モーションの `Microsoft-LICENSE.md` / `UPSTREAM-NOTICE.md`、`THIRD_PARTY_NOTICES.md` を一緒に保持してください。

## 開発時の再ビルド

生成済みの `public/noa-vrm-avatar.mjs` をコミットしているため、サーバー実行時のnpm依存ゼロを維持しています。レンダラーのソースを編集するときだけ、開発ルールに従って許可された環境に固定バージョンのビルド用パッケージを導入します。

```sh
npm run setup:avatar
npm run build:avatar
npm run check:avatar
npm run evaluate:avatar
npm run evaluate:outfits
npm run release:check
```

`setup:avatar` は明示的な開発用インストールです。通常起動やCIの基本回帰検査からは実行しません。既存の同じバージョンのツールを利用する場合、`JEV_AVATAR_BUILD_ROOT` にその `node_modules` を持つプロジェクトのパスを指定できます。生成物・入力ソースのSHAは `licenses/noa-vrm-build.json` に記録します。`evaluate:avatar` は実骨格と実モーションの非描画検査を行い、結果を `data/vrm-motion-evaluation.json` に保存します。`evaluate:outfits` は実メッシュ・MToon材質で300回の着せ替えと復元を検査し、`data/vrm-outfit-evaluation.json` に結果を保存します。
