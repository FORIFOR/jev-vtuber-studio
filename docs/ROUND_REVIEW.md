# Vampire Survivors の振り返りと再開

`src/vampire-show.mjs` は、ゲームオーバーの観測から結果・振り返り・休憩・再開の挨拶を進める。再開の目標は**ゲームオーバーを受信してから約60秒**。結果や振り返りの音声にかかった時間も、この60秒に含める。

## 振り返りの根拠

`roundReviewOf()` は、終了直前の15ゲーム秒内に記録された、生存中の `combat` 観測（最大100件）から台詞を作る。終了時の体力0は「直前から体力が少なかった」という根拠にしない。古い観測、終了後の観測、時刻が不明な観測も除外する。

次回に試す操作方針は、次の順で現在の観測を確認して選ぶ。

| 優先順 | 確認できた事実 | 次回の方針 |
|---|---|---|
| 1 | 速度1.5以上の敵が同時に3体以上いた | `escape_space` |
| 2 | 最大体力が同じ観測間で、体力が最大の25%分以上減った | `health_priority` |
| 3 | 敵数が20体以上増えた | `escape_space` |
| 4 | 最後に確認できた生存中の体力が35%未満だった | `health_priority` |
| 5 | 最後の観測で敵が40体以上いた | `escape_space` |
| 根拠不足 | 上記の事実を確認できない | 原因は不明と伝え、`escape_space` を試す |

台詞には、実際の体力の変化、敵数、速い敵の数などを使う。同じキャラクターの前回の終了記録があれば、生存時間の差も述べられる。前回と同じ着眼点が続く場合、別の確認できた事実があればそちらを話す。話す着眼点を変えただけで操作方針を交互に変更することはなく、方針は表の優先順に従う。

観測した変化は敗因の確定ではない。前回より長く続いたことも、前回の方針の効果を証明しない。「学習して強くなった」「武器が増えたから長く続いた」などとは述べない。次回の方針は、観測を踏まえて試す意図として伝える。

- `health_priority`：経験値より経路の余裕を優先し、体力が少ないときは安全に近づける、観測済みの回復アイテムを優先する。
- `escape_space`：動く敵や操作応答の遅れに備え、進める経路の間隔に余裕を残す。

どちらも既存の操作側が受け付ける値で、任意の命令やモデルの学習更新ではない。回復アイテムや安全な経路が必ずあるとは約束しない。

## 休憩の時計と音声完了

`endedAt` はゲームオーバーを受信した時刻、`targetResumeAt` はその60秒後、`chatUntil` は55秒後。最後の5秒は短い再開の挨拶のために確保する。

| 時点 | 進行 |
|---|---|
| ゲームオーバー受信 | 結果と振り返りを順に用意する。60秒の時計をここから開始する。 |
| 振り返り全体の音声完了 | このラウンドの `review` ACK を記録。55秒の期限まで余裕があれば任意の雑談を行う。 |
| 終了から55秒 | 任意の雑談の期限。振り返りの ACK があれば、再開の挨拶を用意する。 |
| 再開の挨拶の音声完了 | このラウンドの `resume` ACK を記録。60秒より早ければ、その目標時刻までだけ待つ。 |
| 終了から60秒以降 | 両方の ACK がそろった場合だけ、`round_review_completed` を一度送る。 |

生成済みの文章、TTSの完成、タイマー経過だけでは音声完了にならない。複数の音声部分がある場合は、全体の有効な再生完了通知を必要とする。過去のラウンド、拒否された原稿、重複した完了通知では再開しない。完了済みの振り返りや挨拶を、残り時間を埋めるために再投入しない。

振り返りの完了が30秒後なら、追加で60秒待つことはない。完了が60秒を超えた場合は、直ちに再開の挨拶を用意し、その音声完了を待つ。再生中の必要な音声や依存サービスの遅れがあれば60秒を超えるため、厳密な60秒後のゲーム開始は保証しない。操作側が結果画面を離れる時間も別にかかる。

任意の参加のお題は、振り返り完了後に残り15秒以上ある場合だけ案内し、50秒の時点で期限切れになる。雑談の未公開音声は55秒の期限後に出さない。既に再生を始めた音声や必要な返答の完了条件を、待機時間短縮のために省略しない。

## 審査と操作側への引き継ぎ

振り返りも再開の挨拶も `Jev.speech()` を通る。拒否された場合は、別途審査する短い代替原稿を一度用意する。振り返りの代替原稿も元の観測と操作方針を保持する。代替原稿も拒否された場合や、音声の中断が回復回数を超えた場合は `round_review_failed` とし、時間だけを根拠にゲームを続けない。審査の閾値は変えない。

完了イベントを受けた `GameRunner.completeReview()` は、セッション別の完了ファイルにラウンドID・許可された方針・`playbackCompleted: true` を書く。操作側の `auto_session.py` は同じラウンドの完了ファイルを確認してから結果画面を離れ、方針を次回の判断へ渡す。この時点でさらに60秒を追加しない。

## 確認

`test/vampire-review.test.mjs` は、欠損データ、古い体力低下、回復、最大体力の変更、キャラクターの異なる比較、30秒遅延した ACK、期限後の ACK、完了済み音声の再投入防止を検証する。`test/round-transition.test.mjs` は、実際の TalkEngine の審査・複数音声部分・有効な再生通知を含む流れを検証する。

2026-10-01の確認では、過去34ラウンドの観測を入力したオフライン再生から34種類の振り返り文が得られた。これは観測に応じて原稿が変わることの確認であり、本番での音声送出、再開時間、ゲーム成績の改善を実証するものではない。
