# コメント返答のゲーム状態鮮度

## 目指す体験

ノアの返答が、視聴者が見ているゲームの出来事と食い違わないこと。生成待ち、コメント読み上げ、文間の待ち時間に状態が変わっても、古い数値や前のラウンドを現在の状態として話し始めない。

今回の変更は `src/talk-engine.mjs` の既存送出経路に限定する。新しい会話基盤、依存、モデル呼び出し、アバターや画面の装飾は追加しない。Jev の審査条件や拒否後の修復回数は変更しない。

## 見つかった穴と修正

- 通常経路の `boardAt` / `roundAt` は、モデル生成が終わった時点で取得されていた。生成に渡す観測と同じ同期区間で、最初の非同期処理より前にコピーする
- コメント読み上げ経路には `utterance` / `eventId` / `boardAt` / `roundAt` が引き継がれていなかった。同じ情報を読み上げ付きのターンにも保持する
- 従来の鮮度確認は `published === 0` のときだけだった。コメント音声を公開した後の最初のホスト回答と、ホストの2文目も、それぞれ未再生の文の本文で確認する
- キューに入ってから開始通知までの状態変化も、送出ループと正しい id・lease の最初の開始通知で再確認する
- 不要になった返答は理由付きで一度だけ破棄する。読み上げたコメントを再キューへ戻さない。未再生の音声・ストリームを片付け、Abort に反応しないプロバイダーが終わるまでは単一生成枠を維持する

現在再生中の文を、この鮮度確認で強制中断しない。文の終了後に次の文を確認する。既に話した数値が古くなっただけで、その後の数値を含まない文は破棄しない。開始済みの重複 ACK と終了 ACK の扱い、コメント TTL の既存仕様、振り返り・再開案内の完了確認を維持する。

## 確認できる範囲

判定対象は、アダプターのイベント有効性、ラウンド ID・番組内フェーズ、既存の `numbers()` で提供される数値、既存の残り時間チェック。全ての意味的な古さを理解する判定器ではない。HP、武器名、危険の意味など、アダプターの鮮度契約に含まれない変化は今回追加していない。

モデル生成の `comment_reply` と、コメントへの `game_fact` はフェーズ・ラウンドが変わると保守的に破棄する。ゲーム以外の質問でも観測文脈を持つため、独立した返答まで破棄する場合がある。短い固定挨拶 `comment_ack` はこのフェーズ変更だけでは破棄しない。破棄した返答の自動再生成は行わないため、視聴者の質問に最終的に答えられない場合は残る。

開始 ACK は物理的な音声到達の証明ではない。送出から開始通知までの競合では、取消が実際の再生に先行する保証はない。OBS や視聴者側で古い音声が一切聞こえないことを、このテストから主張しない。

## 人工再生の検証

基点: `fix/live-issues-20261006` の `9e483e21a5614efef109ce62a7787d00dfc638aa`。

`test/comment-game-freshness.test.mjs` は、実際の TalkEngine と BlocksShow に人工の観測、注入した会話・審査・短い WAV、ローカルの開始・終了通知を与える。実録画、実 LLM、実 TTS、OBS、YouTube を使った検証ではない。

- 新規回帰16件: 基点では 5 pass / 11 fail、修正後は 16 pass / 0 fail
- 既存7スイートと新規回帰を合わせた確認: 131 pass / 0 fail / 0 skip
- 対象には生成中の数値変更、終了・新ラウンド、読み上げ後の回答、文間、未開始音声、ACK の不正・重複、TTL、Abort 無視、固定挨拶と振り返り・再開の互換性を含む

```sh
node --test --test-concurrency=1 \
  test/comment-game-freshness.test.mjs test/comment-reply.test.mjs \
  test/blocks.test.mjs test/participation-playback.test.mjs \
  test/round-transition.test.mjs test/rc2-regression.test.mjs \
  test/intermission-deadline.test.mjs test/lobby-flow.test.mjs
```

全体の `npm run release:check` は成功扱いにしない。構文検査は成功したが、基点のソースと既存テストに不一致があり、既存の HTTP 試験で完走しなかった。クラウド側のソース検証環境には最新の大きな VRM と一部画像・モーションも取得できておらず、それらの検証も未完。関連する広めの試験群は、基点・修正後で同じ既存6件の失敗と4件の skip があった。

実機確認時は、同じ再生条件でコメント返答率、古い発言、読み上げ後の無回答、文間の長い無音、死亡・結果への反応順を録画から比較する。人気配信者を超えた、配信遅延を達成した、実配信で成功したという結論はまだ出していない。
