# 映像の状態

Studio上部「映像の状態」から開く。http://127.0.0.1:8792/ 、管理キーは既存のStudioから引き継ぐ。配信停止・Jev呼び出しはしない。2秒更新、数値履歴は最大1時間。収集停止は8秒で未確認表示。

OBSの実測FPS、直近区間の描画落ち／エンコード落ち／回線落ち、送信ビットレートを分離する。初回、カウンターリセット、長い取得中断を0%に置き換えない。

追加の画面計測は標準OFF（`GAME_FRAME_PROBE=1`で明示的に有効化）。macOSのScreenCaptureKitでVampire Survivorsのウィンドウだけを320×180・最大60fpsで読み、格子状の画素の変化を比較する。映像・音声は保存しない。表示は**ゲーム内部のFPSではなく映像更新の推定値**。小さな変化を見逃す可能性があり、ウィンドウの描画・キャプチャにも影響される。更新p95と100ms超の間隔を測る。レベルアップ・宝箱・休憩・停止中は低fpsだけで異常判定しない。ゲームの状態が不明なら判定保留。

AIの操作ログ末尾最大2MB・最大30秒を読み、応答時間p95と500ms超の操作間隔を別表示。ゲームブリッジへ二重接続しない。操作間隔は入力停止の確定ではない。視聴端末・CDN・再生バッファの状態は測れない。

## 対処

- 「ゲーム取り込みを再接続」は既存のゲーム専用OBS入力を実際のゲームウィンドウへ再選択する。任意のアプリを映さない。配信、ゲーム、音声を止めない。再操作は60秒空ける。
- Studio「プレビューを休止」は管理画面のプレビューだけを停止。OBSの映像・音声に影響しない。「再開」で戻せる。
- フレームレート、解像度、ビットレートは自動変更しない。原因不明のままゲームや配信を再起動しない。

## 起動

Studioを次に通常起動した際はモニターも起動する。現在の配信中は `npm run performance` を別プロセスで起動できる。同ポートを二重起動しない。Mac用計測器の初回コンパイル：

```sh
mkdir -p data/performance
swiftc -O scripts/game-frame-monitor.swift -o data/performance/game-frame-monitor
GAME_FRAME_PROBE=1 npm run performance
```

画面収録権限が必要。未許可の場合はOS設定で許可する。欠損値を正常なFPSとして扱わない。OBSの計測は画面収録がなくても利用できる。
