# コメント読み上げ → リアルタイム返答 / rc.4

## 何が変わったか

採用した視聴者コメントはVOICEVOXの独立した声で読み上げます。同時に元の**テキスト**を会話モデルへ渡して回答を準備し、コメントの再生終了後、準備できた回答をキャラクターの声で再生します。

```text
YouTubeコメント → ローカル検査 → Jevの採用判定・引用可否
                                     ├─ VOICEVOX：コメント音声を作る → 再生
                                     └─ LLM：本文生成 → Jev出力検査 → ホストTTS
                                                         ↓
                            コメントの再生終了 ＋ 回答音声の準備完了
                                                         ↓
                                        キャラクターが回答を再生
```

GPT-Live-1の音声入力・常時セッションは追加していません。現在設定したOllama／Chat Completions互換／Geminiの文章モデルを引き続き使います。TTSは文章を音にする部品であり、推論を担当するモデルをSupertonicに置換するわけではありません。Supertonicへ変えるだけでGPT-Liveと同品質になるという検証はありません。

## 使うまで

1. 旧版とOBS配信を停止し、rc.4を別フォルダへ展開。起動済み旧版へ上書きしません。
2. VOICEVOX Engine、会話モデル、任意のSupertonicをPCで起動します。
3. `npm start`からControl URLを開き、「AIと声」で設定します。
4. 「採用したコメントをVOICEVOXで読み上げてから返答する」を有効にし、検出した読み上げ用の声を選択。ホストとは異なる声を推奨します。
5. ホストの音声方式を **Supertonic 3** または **VOICEVOX** から選択し、設定を保存します。
6. 実試聴でコメント音声と回答音声を両方再生し、「聞こえた」を確認します。
7. ローカル自動運転で「どの家具が好き？」などを投稿し、コメント→返答の順、声の違い、音量を録画で確認します。その後に限定公開へ進みます。

コメント用VOICEVOXが必須です。ホストをSupertonicにしてもVOICEVOX Engineを停止しないでください。初期設定では既存のホストVOICEVOXを維持し、コメント読み上げだけ有効にします。APIやモデルを無断導入しません。

デモは固定台本と端末の日本語音声です。デモで二つの表示役割が動いても、VOICEVOX／Supertonicが実行されたことや異なる声が出たことの証明ではありません。

## Supertonic 3の導入（任意）

日本語はSupertonic **3**を使用します。公式アーカイブでは開発・サポート・セキュリティ更新の終了が告知されています。固定した版をローカル専用で使い、再配布の際はコードと重みそれぞれのライセンスを確認してください。Voice Builderの新規利用は前提にしていません。

Python 3.11とGitがある環境の例です。まず仮想環境を作り、保存されたSDKのserve追加依存を明示的に導入します。以下は利用者が実行する導入コマンドであり、この配布物のテスト環境で実依存のインストールやモデル推論を完了した記録ではありません。

```sh
python3.11 -m venv .venv-supertonic
.venv-supertonic/bin/python -m pip install "supertonic[serve] @ git+https://github.com/supertone-oss-archive/supertonic-py.git@df0f9686dac7fbbde391b759e2ee5286a3737622"
.venv-supertonic/bin/python scripts/supertonic-local.py --download
```

Windowsでは仮想環境作成に `py -3.11 -m venv .venv-supertonic`、その後のPython実行には `.venv-supertonic\Scripts\python.exe` を使います。PowerShellの実行ポリシー変更は不要です。

`--download`はネットワークとディスクを使ってモデルを取得する明示的な操作です。モデルは `~/.cache/jvs-supertonic-3` に置き、リポジトリや配布ZIPには同梱しません。重みのOpenRAIL-Mライセンスを確認してから実行してください。SDK本体のコミットと重みのrevisionを固定していますが、推移依存まで固定したlockfileではありません。

2回目以降はダウンロードなしで起動します。

```sh
.venv-supertonic/bin/python scripts/supertonic-local.py
```

既に重みがある場合：

```sh
.venv-supertonic/bin/python scripts/supertonic-local.py --model-dir /path/to/supertonic-3 --threads 4
```

この小さなランチャーは公式 `TTS(model='supertonic-3', model_dir=..., auto_download=False)` と公式HTTPアプリを使います。旧ダウンロード先を自動参照させず、明示取得したアーカイブだけを読み込みます。`--threads 4`は初期CPU上限であり最速値ではありません。LLM・VOICEVOX・OBSと同時に動かして調整してください。

起動後、Studioで次を保存します。

```text
ホスト音声方式：Supertonic 3
サーバーURL：http://127.0.0.1:7788
声：F1（F1〜F5 / M1〜M5から選ぶ）
生成ステップ数：8
話速：1.05
```

「モデルと声を検出」は `/v1/health` で `status=ok, model=supertonic-3` を確認します。合成は `/v1/tts` に `text, voice, lang=ja, steps, speed, response_format=wav` を送ります。モデル違い・不正WAV・接続失敗時に、別の声や有料サービスへ自動切替しません。

音声サービスの7788と50021はインターネットやTailscale Serveへ公開しないでください。スマホは従来の8788専用リモコンだけを使います。Supertonicサーバー自身は認証付き公開サービスとして提供する設計ではありません。

## コメントと声の扱い

- 読み上げが有効でコメントが少ないときは、同じ投稿者の別のコメントを1.5秒間隔から受け付けます。直近60秒の対象投稿が3件以下、待機中・返答中が合計2件以下の場合に限ります。それ以外は従来の7秒間隔です。連投による拒否も件数に含め、同文の再送、待機上限、読み上げの長さ、利用予算は維持します。YouTube/Twitch共通の受付で適用し、受信できていないコメントを復元する機能ではありません。
- ローカルの個人情報・指示書き換え検査では、元の文章と表示用に整えた文章の両方を確認します。安全検査と重複検査には不可視文字を除いた表現を使いますが、普通の絵文字の表示は変えません。審査失敗、不完全な採用結果、期限切れは放送せず破棄します。Jevの安全性・個人情報・プロンプトインジェクション・引用可否の閾値は変更しません。
- 引用不可の原文は管理者専用モニターだけに残し、ステージと共有するイベントには本文を含めません。`COMMENT_TTL_MS`（初期値60秒、最大120秒）は受付待ち・審査完了後・発話前で共通に適用します。
- 読むのは採用済み・引用して読めると判定したコメントだけです。全コメントを無条件に放送しません。
- Jevの同じ要求内で「返答対象として採用する」と「原文を引用してよい」を別の質問で検査します。返答してよくても引用不可の場合は、コメントを読まず回答だけにします。判定は未校正で、誤拒否・見逃しの可能性があります。
- 初期の読み上げ対象は120文字以内、音声は10秒以内。長文・URL・ローカル検査に触れる文は読み上げ経路に入れません。勝手な要約を原文として読ませません。10秒超の音声を作った場合は理由を表示し、コメントの読み上げを省略して回答だけにします。長さを理由に同じ音声を繰り返し生成しません。
- 投稿者名は読みません。「コメント。」という区切りと、正規化された本文を読みます。
- 読み上げ中は画面に「コメント読み上げ」と表示し、キャラクターの口パクを止めます。SVG/PNGとVTube Studio口の入力を区別します。
- 読み上げ文をホストの発言記憶に追加しません。ホストが実際に返答した部分だけを再生終了通知後に記録し、完了した対話はコメントと回答を関連付けます。
- APIが遅ければ読み終わった後も待つ場合があります。待ち時間を隠す定型同意や、未審査回答は流しません。
- 読み上げ開始後に回答生成が失敗した場合、そのコメントを自動で何度も読み直さず、保留・破棄理由を記録します。開始前の取消のみ、期限内の候補を一度だけ戻します。
- 生成1件、判定済み返答2件、単一の音声所有者という上限を維持します。スマホは音声所有者になりません。

## 短いコメントへの返答と修復

生成する返答の目的は、そのコメントへの直接回答です。質問には答えを先に、感想には内容に合った短い受け止めを返します。直前の会話と現在の観測を残す一方、次の自動雑談用の `angle`・`returningTo`・`demo` を返信の生成文脈から外し、返信専用の `goal` を使います。短いコメントを無関係な話題や比較へ広げず、通常は1〜2文で完結させます。分からないこと、観測にないゲームの状態、身体的な体験、音量や設定を変更した事実を作りません。

ゲーム番組では、コメント全文が単独の音量報告に一致する場合に、内容に対応する固定返答を使います。「声が小さい気がする」には知らせてくれたことを受け止め、視聴者側の聞こえ方を確認・調整できるとは言いません。「コメント届いてる？」などの質問や、別の依頼を付け足したコメントは全文への回答経路に残します。固定返答でも入力・出力審査と引用可否の確認を通り、審査を省略しません。

生成文が安全性・プライバシー・指示書き換え・誠実さの審査を通り、内容面だけで `no_progress` となったときは、一度だけ修復します。返信の修復には、未放送の直前案と、取得できた審査スコアで不足が分かる項目を渡します。既出内容の繰り返しか、コメントへの直接回答が不足したかに合わせ、回答そのものを修正します。ローカルの繰り返し検査で止まった未審査文は、修復へ再投入しません。初回と修復の計2案が拒否されたら破棄し、通るまでの再生成や無関係な定型返答への置換はしません。固定台詞はモデルで書き直しません。

安全性・誠実さが不十分な `unsafe_or_uncertain`、拒否理由が不明な結果、引用禁止の原文を復唱した生成文には、この修復を行いません。引用不可でも話題への返答はできますが、原文全体の復唱や短い原文の明示的な引用を生成文に検出した場合は、音声へ渡さず破棄します。修復の直前案や審査スコアをステージ共有イベントへ追加しません。

審査の閾値は変更していません。通常の生成返信は `novel`・`progress` ともに `.7` 以上に加え、`safe >= .94`、`private < .08`、`injection < .2`、`honest >= .85` を必要とします。短い固定応答は従来どおりコメントへの適合性を審査し、安全性・誠実さの条件も維持します。入力審査では公開キャラクター名と通常の受信・音量確認を文脈として説明しますが、同じコメント内の他の個人情報や不適切な依頼を免除しません。

返信の `novel` は、コメントに必要な事実や方針の短い再説明を認め、毎回新しい話題を要求しません。無関係な準備・意気込み・賛辞の繰り返しは引き続き拒否します。入力されたコメントが実際に届いたことは説明しますが、その文章の内容が事実とは扱いません。

この変更は全てのコメントへ返答できる保証ではありません。安全なコメントでも判定の誤拒否、返信案の不適合、生成・審査・音声処理の失敗で返答を破棄する場合があります。生成文脈と審査文脈を揃える修正であり、拒否された回答を通す例外は設けません。

## 返答失敗の記録と休憩中の生成期限

コメントの破棄件数を維持しながら、今後の出力拒否は次の理由を区別して記録します。過去の `content_stalled` だけから、当時の安全性拒否と内容面の拒否を判別できるとは扱いません。

| `chat_drop` の理由 | 対応するメトリクス | 意味 |
| --- | --- | --- |
| `content_no_progress` | `comment_drop_content_no_progress` | 一度の修復後も内容面の審査を通らなかった |
| `output_unsafe_or_uncertain` | `comment_drop_output_unsafe_or_uncertain` | 安全性・誠実さの拒否、または拒否理由が不明 |
| `output_quote_denied` | `comment_drop_output_quote_denied` | 引用不可の原文を生成文が復唱・引用した |

コメント音声の公開後に回答が拒否された場合、理由には `interrupted_` が付き、メトリクスは例えば `comment_drop_interrupted_output_unsafe_or_uncertain` になります。読み上げを終えた後に回答を破棄し、同じコメントを再度読まず、内容の拒否を音声サービスの障害や再試行として数えません。未公開の場合も、出力審査で拒否された候補を受付待ちへ戻しません。

Vampire Survivorsのゲームオーバー後は、終了時点から約60秒の休憩を設け、そのうち任意の雑談は55秒までです。残り時間で再開案内を準備します。任意の雑談だけに生成期限を付け、期限に達したら進行中の生成・審査・音声要求へ中止を通知します。準備済みでも未再生の任意雑談は期限後に放送しません。中止に応答しない要求との重複生成は行わず、単一の生成枠を維持します。すでに再生している発言、必要な振り返り・再開案内、コメントへの返答は、この任意雑談の期限で打ち切りません。

## 遅延と費用の見方

区別して計測する値は `comment_to_read_ms`（アプリ受信→読み上げ開始ACK）、`comment_to_answer_ms`（アプリ受信→本回答の開始ACK）、`read_to_reply_gap_ms`（読み上げ終了ACK→本回答開始ACK）。VOICEVOX/LLM/TTSの生成時間も別に記録します。全てローカル通知基準で、視聴者に聞こえた時刻ではありません。

同時処理によって回答準備を読み上げ時間と重ねますが、受信→本回答が必ず短縮するわけではありません。短い回答が先に完成した場合でも、読み上げを最後まで待つ設計です。読み上げなしの経路より追加TTS・再生時間は増えます。

この実装では読み上げ音声をLive APIや音声認識へ再入力しないので、そのための音声入力処理・常時接続を作りません。ローカルTTSは電力・CPUを使います。Jev・選択したクラウド文章モデルの利用料金は残ります。TTS呼出上限は両方の声を合算し、回数上限を金額上限とは扱いません。
