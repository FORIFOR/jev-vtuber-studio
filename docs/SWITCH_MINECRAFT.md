# Nintendo Switch / Minecraft 配信の準備

## StudioからUGREEN等をつなぐ（macOS）

Studio右上の **Switch接続**（`/switch`）で、機器の選択から30秒録画まで進められます。

1. Switchのドックへ電源とHDMIをつなぎ、HDMIをキャプチャー機器のIN、USBをMacへ接続します。
2. **デバイスを探す**を押し、実際に接続した映像・音声デバイスと画質をそれぞれ選びます。内蔵カメラ・マイクは選びません。
3. **OBS専用シーンを準備**で `JVS Switch Capture` を作成します。既存シーンと配信先は維持します。1080pは機器の対応プリセットがある場合だけ適用し、60fpsやYUY2は強制しません。
4. **プレビュー静止画を更新**で信号を確認します。動き・音は静止画では確認できません。
5. **30秒のローカル録画を開始**を押し、Switchで音の出る操作をします。OBSのグローバルマイク・デスクトップ音声を一時ミュートし、Switch専用シーンへ切り替えて録画します。終了後は元のシーン・ミュート状態へ戻します。手動で別シーンへ移った場合、その選択を尊重します。
6. OBSの「ファイル → 録画を表示」から再生し、映像・ゲーム音・二重音の有無を確認します。ゲーム音のモニタリングは既定でOFFです。イヤホンで常時聴く設定はOBS側で機器を指定して確認してください。

配信・録画・リプレイ保存・番組の動作中は変更を拒否します。このページは外部配信やVampire Survivorsの自動プレイを開始しません。設定済みは信号や品質の検証済みを意味しません。Switchシーン選択中に通常番組の開始を押すと、別ゲームが起動しないよう案内します。

OBSとの接続が切れた場合は、録画停止をOBSで確認してから「OBSで停止を確認したので再確認」を押してください。別の録画を引き継いで停止することはありません。Studio自体が終了した場合もOBSの録画状態を確認してください。

音声候補は既存OBS音声入力のデバイス一覧から取得します。音声入力が一つもない環境では、既定マイクを勝手に開かないため自動列挙を保留します。OBSにキャプチャー機器用の音声入力を用意して確認してください。既存ソースで同じ機器を使っている場合も二重取り込み防止の案内が出ます。


この文書と `switch:check` は、**人がSwitchを操作する配信を準備するためのもの**です。Pi 4経由の自動操作、画面認識、Minecraftの自律プレイ、ゲーム内容に沿う自動実況は実装していません。映像をOBSへ入れることと、ノアがゲームの状態を理解して操作することは別です。ノアの通常の雑談・コメント反応は、音声と各サービスの接続を別に確認します。

2026-10-01の準備時点で、UGREEN 25773 / CM726は購入済みとの申告がありますが、このMacで実機映像・ゲーム音を確認した記録はありません。別Macで報告されたSwitch専用ソースはGitHub上の全5ブランチ・2 PRには見つからず、この診断と手順を新規追加しました。

## 1. 現在のVampire配信を保護する

ライブ中はシーン、プロファイル、配信先、解像度、フレームレート、ブラウザソースURL、音声ミュートを変更しません。Studioのゲーム番組をSwitchの名前に書き換えて起動することもしません。現在のVampireコントローラが起動・OBSのシーンを作り直す可能性があるためです。

以下の診断は読み取りのみです。OBS WebSocketに接続してGet系リクエストを送り、OSのUSB/カメラ機器名を一覧にします。**配信・録画・ゲーム・カメラは開始しません。** API課金もありません。OBSキー、ブラウザURL、機器固有IDは出力しません。

隔離チェックアウトから、既存Studioの設定ファイルを明示して診断できます。以下のパスは実際の配置先へ置き換えます。

```sh
cd /path/to/review-checkout
npm run switch:check -- --studio-dir /path/to/running-studio
```

Gitから別の場所へ取得した場合は、チェックアウト内で `npm run switch:check` を実行します。既定ではそのチェックアウトの `.env` / `data/settings.json` だけを読みます。`--studio-dir` で指定した先のJavaScriptは実行しません。OBS接続はlocalhostだけを許可します。`--pi-host raspberrypi.local` はPi接続先を指定したという記録にすぎず、SSH接続・到達性確認をしません。

診断の解釈：

| 表示 | 意味 |
| --- | --- |
| `obs.connection: connected` | WebSocketの認証・接続に成功。映像/音声の確認成功ではない |
| `wait_until_current_output_ends` | 配信・録画等が動いている。構成変更は終了後 |
| `output_state_unknown` | 出力状態のGetに失敗。停止中とは判断できない |
| `capture.availability: candidate_detected` | USBまたはOBSの一覧にキャプチャ機器らしい名前がある。Switchの信号が入った証明ではない |
| `no_matching_candidate_observed` | 既知の名称の候補なし。汎用名・列挙制限の場合もあり、未接続と断言しない |
| `configuredVideoSources` | OBSに存在する映像キャプチャのソース名。接続状態とは別 |
| `videoSignal` / `audioSignal: unverified` | 実映像・試聴はこの読み取り診断では検証しない |
| `pi.connection: unknown` | Pi接続先未指定。`configured_unverified` でも実接続未確認 |
| `manualBroadcast.ready: false` | ローカル録画と試聴を人が完了するまで、準備完了を自動宣言しない |

終了コード0は「診断を実行できた」、1はOBS接続等を確認できなかった、2は引数/設定の問題です。0を「配信できる」と扱わないでください。グループ内のシーン項目は展開せず、全体の入力一覧を別に表示します。極端に多数のシーン・入力は上限付きです。

## 2. ライブ終了後の配線

1. TVモード対応のSwitchを、ACアダプターで給電したドックへ挿します。Switch LiteはTVモードに対応しません。[任天堂の接続方法](https://support.nintendo.com/jp/switch/playmode/index.html)
2. ドックのHDMI OUT → キャプチャ機器のHDMI INを接続します。パススルーOUTを備える機種ならOUT → モニターへつなぎ、操作はそちらの画面を見て行います。購入品にOUTがあるかは実物/付属説明書で確認します。
3. キャプチャ機器のUSBデータ端子 → Macへ接続します。給電専用ケーブルは使いません。可能なら他の高負荷機器と同じハブを避けます。
4. SwitchをHOME画面にし、もう一度診断します。UGREENという名前で出ない場合はOBSの機器選択肢を確認します。

UGREEN購入名だけでは、この個体と接続経路で使える解像度/FPSは確定できません。最初は実機が提示する **1920×1080 / 30fps**、選択できなければ **1280×720 / 30fps** から録画確認します。60fpsや4K入力の広告表記を、そのままUSB取り込み性能の保証として扱わないでください。

## 3. 専用OBS構成を手動で作る

配信、録画、リプレイバッファ、Studioの番組がすべて停止している状態で行います。OBSの現在のプロファイルとシーンコレクションを書き出して退避し、Switch確認用に複製します。

- 新しいシーン名の例：`星藍ノア - Switch`。既存Vampireシーンはそのまま残します。
- 「映像キャプチャデバイス」を追加し、実物の機器を選びます。Mac全画面のキャプチャではありません。[OBS公式のキャプチャソース](https://obsproject.com/kb/video-capture-sources)
- ゲーム映像をNoa Stageのゲーム枠へ配置します（現行横型の枠は x=48, y=120, 幅1120, 高さ630）。Stageの3Dアバターは軽量設定で確認します。配信中に既存Stage URLを差し替えません。
- 既存のVampireゲーム画面・ゲーム音声ソースは、このSwitchシーンに持ち込みません。
- ゲーム音はキャプチャ機器が提供する音声入力を使います。映像ソースで音が既に入っていれば、同じ機器を二重に追加しません。追加が必要な場合のみ音声入力キャプチャを用意します。[OBS公式の音声ソース](https://obsproject.com/kb/audio-sources)
- ノアの声はStageの既存音声経路を使います。試聴時のモニター音をデスクトップ音声で再取得すると二重になるため、録画を再生して一度だけ聞こえるか確認します。マイクは必要なときだけ明示的に有効にします。

この準備には、OBSを変更する `apply` コマンドはありません。**Vampire番組の「配信開始」からSwitch配信は始めないでください。**

Switchの映像でノアが実況する番組は、`capture.kind: "switch"` のゲーム企画（例：`noa-smash`、`docs/PROGRAMME.md`）として始めます。その番組は専用シーン `JVS Switch Capture` を使わず、自分のシーン `Jev Studio - <ゲーム名>` に Stage と `JVS Switch Video`／`JVS Switch Audio` を置くので、このページで選んだ機器がそのまま映り、ここでの所有権チェックも通ります（番組シーンだけが入力の共有を許されます）。

## 4. 10分のローカル録画を合格条件にする

公開送信はせず、OBSのローカル録画で確認します。

1. 最初の1分：HOME画面から実際のゲームへ入り、動く映像とゲーム音を確認します。
2. 続く数分：人が操作し、3Dノアの動作・口パク・声を同時に出します。通常コメントの読み上げ/返答も、接続できているサービスで実コメントを1件確認します。未取得のサービスは成功扱いにしません。
3. 10分継続：OBSの統計でレンダリング遅延/エンコード遅延のフレーム欠落が増え続けないか、Macのメモリ圧力、音切れ、映像停止を見ます。失敗したら3Dの負荷、解像度、fps、USB経路の順に切り分けます。
4. 録画ファイルを再生：ゲーム音とノアの声が一度ずつ聞こえる、口パク・ゲーム映像の音ズレが許容範囲、不要なマイク/通知音が入らないことを確認します。WebSocket接続成功だけで合格にしません。
5. 同時配信先・タイトル・公開範囲・コメント接続を確認してから公開します。録画テストと公開配信の操作は別です。

## 5. Pi 4による自動操作は別工程

この変更ではPiソフトの導入、Bluetoothペアリング、Switchへの入力、SSH鍵、映像のAI送信を行いません。Pi 4の購入/起動、OS、接続先、Switchに対応した操作方法の実証が必要です。その後も、停止時の全入力解除、再接続時の勝手な操作防止、Minecraftのテスト用ワールド/セーブ保護、モデル費用上限を実装・検証してから自動プレイへ進みます。

**明日の手動Switch＋3D配信**の前提は、実物のSwitch/ドック/キャプチャカードの接続と、上記10分録画の合格です。**Piによる自律プレイ**は、その準備が完了しても別途未完了です。
