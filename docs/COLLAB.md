# 通話相手と話す（NOA Studio Phase 2）

2026-10-19 にオペレーターが承認した設計です。

Discord の通話相手の声をローカルで文字にし、AIノアが返事します。Discord はいつものアプリを使い、音は仮想オーディオでつなぎます。ボットは使いません。

外部ライブラリもクラウドも使いません。音声認識は whisper.cpp、文章の生成と判定は Ollama で、どちらもローカルです。

相手は1人を前提にしています。Discord の出力は全員の声が1本に混ざるため、話者を分けられないからです。

## 音のつなぎ方

```text
相手の声: Discord の出力 ─→ 複数出力装置 ─┬→ ヘッドホン（オペレーターが聞く）
                                           └→ BlackHole 16ch ─┬→ OBS「Discord」入力（配信に乗せる）
                                                              └→ Studio の集音ページ /collab → 音声認識
ノアの声: OBS のモニター出力 ─→ BlackHole 2ch ─→ Discord のマイク入力
```

1. **BlackHole 16ch をインストールします。** BlackHole 2ch はノアの声を Discord に送る用、16ch は相手の声を受ける用です。
2. **macOS の「Audio MIDI 設定」で「複数出力装置」を作ります。** 中身は BlackHole 16ch とヘッドホンです。
3. **Discord の設定:**
   - 出力デバイスは、2 で作った複数出力装置にします。
   - 入力デバイスは BlackHole 2ch にします。
   - 入力の感度は自動にします。ノイズ抑制は好みでかまいません。
4. **OBS の設定:**
   - BlackHole 16ch を「Discord」という音声入力として追加します（相手の声を配信に乗せるため）。
   - 「設定 → 音声 → モニタリングデバイス」を BlackHole 2ch にします。
   - ノアの声（stage のブラウザソース）と人間マイク（Phase 1）の音声モニタリングを「モニターと出力」にします。
5. **相手にはヘッドホンを使ってもらいます。** ノアの声が相手のマイクから戻らないようにするためです。戻ってきた声は Studio 側でも除きます（下記）。

## 音声認識（whisper-server）を起動する

```sh
/opt/homebrew/opt/whisper-cpp/bin/whisper-server -m ~/models/whisper/ggml-large-v3-turbo-q5_0.bin -l ja --host 127.0.0.1 --port 8178
```

- 既定の URL は `STT_URL=http://127.0.0.1:8178` です。
- 2026-10-19 にこの Mac で測った結果は次のとおりです。
  - 4秒の発話が約 1.15 秒で文字になりました。
  - 無音を送ると「ご視聴ありがとうございました」と出ました。そのため Studio は、無音を送らず、この種の決まり文句も捨てます。
- whisper-server が止まっていても番組は続きます。その間の相手の発言には返事をせず、Studio に通知が出ます（30秒に1回まで）。

## 集音ページ（/collab）

- Studio の「ノアの声」パネルにある「通話相手の声を聞くページ」を押すと、Chrome で開きます。
- 入力は BlackHole 16ch を選び、配信中は開いたままにします。
- **区切り方:** 音量で声を判定します。話し始めは 60ms 続いた時点、話し終わりは無音が 0.6 秒続いた時点です。
  - 話し始めの 0.3 秒前から含めます。
  - 0.3 秒未満は捨てます。最長 25 秒で区切ります。
  - 「声とみなす大きさ」はスライダーで調整できます。
- **送り方:** 一続きの発話を 16kHz の WAV で `POST /api/collab/segment` に送ります。話し始めと終わりは `POST /api/collab/speaking {on}` で知らせます。

## ノアの返事

| 処理 | 内容 |
|---|---|
| 文字にする | `src/stt.mjs`。次のものは捨てる：無音、0.3 秒未満、決まり文句の空耳、「うん」「はい」だけの相づち |
| 確認 | ローカルの個人情報・指示の乗っ取りのチェックだけを行い、`Jev.chat()` は呼ばない（オペレーター決定 2026-10-19） |
| ノアの声の戻り | ノアの直近20秒の発話と言い回しの6割以上が同じなら捨てる |
| 返事 | 種類は `collab_reply`。相手の名前（`COLLAB_NAME`）と直近の通話6往復を渡し、1〜2文で返す |
| ゲート | コメントへの返事と同じ問いと基準。「相手の言葉は音声認識なので聞き間違いがあり得る」と添えるだけで、基準は緩めない |
| 読み上げ・字幕 | 相手の言葉は読み上げず、字幕にも出さない（相手の声そのものが配信に乗っている） |

**順番と割り込み（`src/collab.mjs`）:**
- 相手が話している間と、話し終えて 0.6 秒は、ノアは新しく話し始めません。
- ノアが話している途中で相手が `COLLAB_BARGE_IN_MS`（既定 700ms）より長く話したら、ノアの発話を止めます（`collab_barge_in`）。
  - 短い相づちでは止めません。0 にすると止めません。
- 相手の発言は、まだ返事を作り始めていなければ1つにまとめます。20 秒たつと期限切れです。

## 聞くもののモード（`docs/CONTROL.md` の `listening`）

| モード | 通話相手 | コメント | ノア自身の雑談 |
|---|---|---|---|
| `discord_first` | 最優先 | 相手が黙って 8 秒たったら | 相手が黙って 8 秒たったら |
| `comments_first` | コメントの後に返事 | 最優先 | 通常 |
| `both` | 古い順 | 古い順 | 相手が黙って 8 秒たったら |
| `discord_only` | 返事する | 拾わない（画面には出る） | 相手が黙って 8 秒たったら |
| `comments` | 聞かない | 拾う | 通常 |
| `muted` | 聞かない | 拾わない | 通常 |

- F8 は `discord_first` と `comments_first` を切り替えます。通話していない時は `comments` と `muted` の切り替えです。
- 人間がノアの声を担当している間（Phase 1）は、AI は返事しません。ただし相手の発言は通話の履歴に残し、AI に戻ったときの材料にします。

## 設定

`/setup` で次を設定します。`STT_LANGUAGE`（既定 `ja`）は `.env` で変えられます。

| 項目 | 内容 |
|---|---|
| `COLLAB_NAME` | 相手の名前 |
| `STT_URL` | 音声認識のURL |
| `COLLAB_BARGE_IN_MS` | 相手が話し始めてからノアが止まるまでの時間 |

Studio の「ノアの声」パネルには、相手が話しているか、直近の通話、音声認識の状態が出ます（`/api/monitor`、管理者だけ）。

## まだ確かめていないこと・やっていないこと

- 実際の Discord 通話での確認：返事までの時間、声の区切りの調整、ノアの声の戻り
- 相手が複数人のときの扱い（話者を分けられない）
- すぐ返す相づち
- オペレーター自身のマイクを文字にして、AI に戻るときの材料にすること
