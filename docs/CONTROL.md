# ノアの声と聞くものの切り替え（NOA Studio Phase 1）

2026-10-19 にオペレーターが承認した設計です。配信を止めずに、次の2つを何度でも切り替えられます。

- **声**：ノアとして話すのは AI か人間か
- **聞くもの**：ノアがコメントを拾うか（`comments`）、拾わないか（`muted`）

実装は `src/control.mjs`、状態は `engine.control`（`status().control`）にあります。

## 声（`voice: 'ai' | 'human'`）

| | AI | 人間 |
|---|---|---|
| 誰の声が出るか | 生成 → 出力ゲート（`Jev.speech()`）→ 音声合成された発話 | `HUMAN_VOICE_MODE` で決まる（`docs/HUMAN_VOICE.md`）。そのまま／RVC は OBS の入力 `OBS_HUMAN_MIC_SOURCE`、コハクで読み直しは人の言葉を AI と同じ音声合成で読み直す（OBS マイクは閉じたまま） |
| 出力ゲート | すべての発話が通る | **人の発話は通さない**（オペレーター決定 2026-10-19。オペレーターが責任を持ち、切り替えはすべて記録する） |
| 生成・判定・コメント選別 | 通常どおり | 止まる（LLM も判定も呼ばない） |
| ノアの口 | 発話の音声に合わせて動く | 人間マイクの音量で動く（OBS の音量メーター → `human_level`） |
| 字幕 | 発話の文 | 出さない（音声認識は Phase 2） |

### 守ること：AI の声と人間マイクを同時に流さない

- **AI → 人間**：まず新しいターンを止め、話し中の発話と準備中の発話を中断します（`voice_handoff`）。そのあと人間マイクの音を出します。
  - マイクを出せなかったときは `micError` を記録して Studio に表示します。AI は止めたまま（無音）にします。
- **人間 → AI**：先に人間マイクを止め、OBS が止まったと返すのを待ちます。確認できてから AI が話し始めます。
  - 止まったと確認できないときは人間の状態のまま残し、エラーを返します。
- **停止・緊急停止・番組開始**：どれでも AI に戻し、聞くものは `comments` にし、人間マイクを止めます。
  - マイクを止められなかったときは記録して通知します。

### 再開時の扱い

AI に戻った直後の最初の発話には `humanHandoff: { minutes }` を渡します。モデルには「中の人が話していた。内容は分からないので触れない」と伝えます（`src/providers.mjs`）。

### 番組の終わり

人間が話している間にお別れの時間が来ても、AI は割り込みません。Studio に「お別れの時間です」と出すだけです。

AI に戻すか「挨拶して終了」を押すと、お別れが始まります。「挨拶して終了」は先に AI に戻してから、お別れを始めます。

ただし番組時間の上限（`SESSION_MINUTES`）はそのまま効きます。

## 聞くもの（`listening: 'comments' | 'muted'`）

- **`muted` の間**：コメントは画面のチャット欄に出ますが、ノアは拾いません（`comments_paused` として記録）。
- **一時停止との関係**：Studio にもともとある「コメント受付を一時停止」と同じスイッチです（`commentsPaused` は `listening` を読む）。
- **人間が話している間に来たコメント**：AI に戻ったあとに拾われることがあります。ただし今の期限（受付後 60 秒、候補になってから 120 秒）を過ぎたものは捨てられます。
- **通話相手（Phase 2）**：`discord_first` / `comments_first` / `both` / `discord_only` を追加しました（`docs/COLLAB.md`）。`discord_only` もコメントは画面に出しますが、拾いません。

## 操作

| 操作 | どこから |
|---|---|
| 声を AI／人間にする | Studio「ノアの声」のボタン、F6（Studio の画面を開いている時）、`POST /api/control {action:'voice', to:'ai'|'human'}` |
| 聞くもの | Studio の「ノアが聞くもの」、F8（通話優先⇄コメント優先、通話なしならコメントのON/OFF）、`POST /api/control {action:'listening', to}` |

- 操作はどれも管理者だけが使えます。人間にできるのは番組の開始後だけです。
- 人間マイクは `/setup` の「人間マイクのOBSソース名」（`OBS_HUMAN_MIC_SOURCE`）で設定します。空欄なら人間を選べません。
  - ソースはオペレーターが OBS で作ります。Studio はミュートと解除をするだけです。
- 監査ログ（`data/audit*`）には `control_handoff`、`control_handoff_refused`、`control_listening`、`control_mic_off_failed` が残ります。

## 瞬時の交代（Phase 4、2026-10-19）

### 切り替えの処理
- **順番に処理する:** 声の切り替えは1本の列で順に処理します。処理中は `control.switching` が立ち、Studio のボタンは押せません。
- **連打の扱い:** 250ms 以内の同じ操作は1回とみなします。断られた操作（番組前など）は覚えておかないので、押し直せばそのまま新しい操作になります。

### 交代のタイミング（`HANDOFF_TIMING`）
- **`immediate`（既定）:** AI の声を 120ms で絞ってから止めます。stage では、WAV とストリーミングの再生経路を1つの音量つまみに通しています。
- **`sentence`:** 今の文を言い終えてから交代します（最大4秒）。どちらの場合も、押した時点で次の文は始まりません。

### 待たせない再開
**① 再開用の一言を先に用意する**
- 人間（または無音）の間に、AI が再開して最初に言う一言を、生成・ゲート・音声合成まで済ませて1つ用意しておきます。
- 作るのは、人間の声が2秒以上途切れたときだけです。
- 使えるのは新しいものだけです。
  - コハクで読み直しの場合は、人間の新しい発言があれば古いとみなし、60秒までです。
  - それ以外は45秒までです。
- AI に戻すと、次の周回ですぐ流れます。

**② つなぎの一言（`RESUME_BRIDGE`、既定オン）**
- 用意が間に合わなかったときは、決まった短い一言を流します。例：「うん、じゃあ続けるね。」。
- その間に本番の発話を作ります。
- つなぎの言葉は、番組で最初に交代したときに一度だけゲート（安全面の確認だけ）と音声合成を済ませます。
- 順番に使い、5分に1回までです。

### ノアを黙らせる（MUTE NOA、F9）と AI 再開（AI RESUME、F10）
- **`voice: 'none'`:** AI も人間マイクも黙ります。人間から `none` にするときも、先にマイクを止めて確認します。
- **F10:** `none` からでも人間からでも AI に戻ります。「待たせない再開」も使います。

### 口の動き
OBS の音量メーター用の接続は、番組開始時から張っておきます。音量は人間が話しているときだけ口の動きに使うので、最初の一言から口が動きます。

### 交代時間
- **AI停止まで:** ボタンを押してから、stage が AI の声を消し終えて `/api/renderer/handoff` を報告するまでです。
- **AI再開まで:** ボタンを押してから、AI の最初の発話の再生が始まるまでです。
- Studio に直近の値と、直近10回の中央値が出ます（`control.latency`）。
- **目標:** 停止まで 100ms 以内、再開は用意した一言がある場合に 500ms 以内です。
- **ヘッドレスChromeで確かめた結果（2026-10-19）:** 交代の合図からフェードを終えて報告が届くまで約135ms でした（そのうちフェードが 120ms）。

## ライブ操作パネルとショートカット（Phase 6、2026-10-19）

### ライブ操作パネル（`/control`）
Studio の「ライブ操作パネル」から開きます。配信には映らない、オペレーターだけの画面で、1画面に次の操作と状態がまとまっています。

| 欄 | 内容 |
|---|---|
| 声 | AI／人間／無音 |
| 聞くもの | 6つのモード |
| ゲーム | AI／人間／OFF。OFF はゲームを止めます（2回押し） |
| 表情 | 自動／手動と、手動のときの表情（ふつう・うれしい・笑う・わくわく・びっくり・困った・考え中・照れ） |
| 入力の状態 | 通話、人間マイク、コメント、ノアの声 |
| 大きいボタン | TAKE OVER／AI RESUME／MUTE NOA／STOP ALL（緊急停止。2回押し） |
| ショートカットの割り当て | 欄を押してからキーを押すと変わります。保存先は `data/hotkeys.json` です |

### 表情を手動にする（Avatar Controller）
- 手動（`control.avatar = 'manual'`）の間は、オペレーターが選んだ表情（`control.face`）を保ちます。発話や出来事による自動の表情や反射は出しません。口の動きは声に合わせて動き続けます。
- 自動に戻すと、今までどおり自動で表情が付きます。
- 番組を止めると自動に戻ります。

### ショートカット
- **初期設定:**

  | キー | 操作 |
  |---|---|
  | F6 | AI⇄人間（声） |
  | F7 | AI⇄人間（ゲーム操作） |
  | F8 | 通話優先⇄コメント優先 |
  | F9 | MUTE NOA |
  | F10 | AI RESUME |

- **割り当てられる操作:** 上の5つに加えて、TAKE OVER と「表情の自動⇄手動」も割り当てられます。
- **使えるキー:** F1〜F19、または修飾キー（Ctrl／Alt／Shift／Cmd）と英数字の組み合わせです。修飾キーなしの英字は、文字入力とぶつかるので使えません。
- **どの操作を行うかは、サーバーが今の状態を見て決めます**（`POST /api/control {action:'hotkey', name}`）。Studio、パネル、全体のショートカットのどこから押しても同じ動きになります。

### どのアプリが前面でも効くショートカット
- Studio を動かしている間に `npm run hotkeys` を実行します。
- 初回に `scripts/hotkeys.swift` を `data/bin/noa-hotkeys` に組み立てます。キーの受け取りには Carbon の `RegisterEventHotKey` を使うので、アクセシビリティの権限は要りません。
- 割り当ては10秒ごとに読み直し、変わっていたら登録し直します。
- Mac のファンクションキーをそのまま使うには、「F1、F2などのキーを標準のファンクションキーとして使用」をオンにするか、fn を押しながら押します。
- 他のアプリがすでに使っているキーは登録できず、その旨を表示します。

## Phase 1 でやっていないこと

- **AI の声のフェードアウト**：Phase 4 で入りました（交代のときだけ。ブラウザの読み上げ（デモ用）はすぐ止まります）。
- **`/mobile` からの操作**：遠隔操作の入口は開始・停止・緊急停止だけに絞ってあり、ここにマイクの切り替えは足していません。
- **どのアプリが前面でも効くショートカット・キーの割り当て変更**：Phase 6 で入りました（`npm run hotkeys`、ライブ操作パネルで割り当て）。
- **ボイスチェンジャー**：Phase 3（`docs/HUMAN_VOICE.md`）で「コハクで読み直し」と RVC の準備が入りました。
- **ゲーム操作の切り替え**：Phase 5（`docs/GAMES.md`「配信中のゲーム操作の切り替え」）で入りました。F7 で切り替えます。声とは別々に切り替えられます。
